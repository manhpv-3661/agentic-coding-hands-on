# Review: UI refactor & cleanup (plans/260709-1710-ui-refactor-cleanup)

Scope: full diff (unstaged + staged `git rm`) across phases 00-05. Verified against plan/phase files, independently re-ran `npx tsc --noEmit` and `npx vitest run`.

## Blocking

1. **`app/login/page.test.tsx:161-172` — real, reproducible `tsc --noEmit` failure (TS18048 ×3), contradicting the tester report's "Typecheck: 0 errors" claim.**
   The rewritten JSX-tree walker guards with `child?.type === "main" || (child?.props && typeof child.props.children === 'object')`. Because the condition is an `A || (B && C)` union, entering the `if` block does not prove `child.props` is defined (branch could be true via `A` alone) — TS correctly refuses to narrow, so `child.props.children` at lines 164/165/166 is "possibly undefined". Reproduced fresh (cleared `tsconfig.tsbuildinfo`, ran `npx tsc --noEmit` twice). This is a real compile error, not stale cache. Not in this refactor's declared scope (login page isn't part of phases 00-05) but it's in the diff and it's broken right now — must be fixed (e.g. `if (child?.props && (child.type === "main" || typeof child.props.children === "object"))`, or split into two conditionals) before merge, or `npm run build`/CI's type-check step will fail.

## Should-fix

2. **`site-footer.test.tsx` suite cannot execute at all — the refactor's own regression tests for the riskiest change (footer `NavLink` variant migration + unified `isActive`) never run.**
   `app/fonts.ts:30` calls `localFont(...)` at module scope; the test's `vi.mock` only covers `next/font/google`, not `next/font/local` → `TypeError: default is not a function`, 0 tests execute (confirmed via `npx vitest run app/components/home/site-footer.test.tsx`). This bug is **pre-existing** (reproduced identically on `git stash`, i.e. present before this refactor touched the file), so it's not something this refactor broke — but this refactor is exactly the one that added the two new tests meant to lock in the nav-link-variant/isActive-unification behavior described in phase-04's own risk table ("Confirm pathname defined at footer; test both header & footer paths"). Those tests currently provide zero protection. Same gap affects `root-further-content.test.tsx` and `sun-kudos-section.test.tsx` per the tester report. Worth a one-line fix (add the `next/font/local` mock, same pattern already used in 10+ other test files) so the new coverage actually means something.

3. **`resolveAwardCategoryMeta`'s shared `console.warn` message text is not actually identical to both prior call sites, despite the doc comment's claim.**
   `lib/awards/award-category-meta.ts:44` hardcodes `` `[${callerLabel}] no title/dict metadata for award slug "${slug}", skipping card` ``. The old `award-detail-data.ts` warning said `"no title/dict metadata..."`; the old `home/awards-section.tsx` warning said `"no title metadata..."` (no `/dict`). The shared helper silently applies the `award-detail-data` wording to both callers, so `awards-section.tsx`'s warn text changed. Doc comment claims `callerLabel` "reproduces each caller's own warn-message prefix exactly" — true only for the bracketed prefix, not the message body. Zero functional impact (dev-console only, no test asserts the literal string), but it does violate this refactor's own "byte-identical" pledge and the comment overstates what was preserved. Fix: either accept/document the minor drift explicitly, or thread the differing body text through a parameter too.

4. **`app/login/page.test.tsx`'s rewritten tree-walker (lines ~154-181) is fragile/hard-to-maintain**, independent of the type error above: comments like "This is likely the PageGutter rendered as main" and a heuristic fallback (`if (!main) { main = element.props.children[1] }`) suggest the author wasn't fully sure of the actual tree shape. Since this test exists specifically to catch a real prior bug (duplicate hardcoded error strings), a guess-based traversal undermines confidence in it. Consider `render()` + DOM queries (already used everywhere else in this codebase) instead of manually walking the React element tree.

## Nitpicks
